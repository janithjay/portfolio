## Problem

A small cleaning robot has to cover a floor on its own: avoid furniture, never fall down stairs, and keep moving. The usual escape move, backing up, was ruled out. [ADD THE REASON: e.g. no rear sensors, so reversing is driving blind; or the brush and vacuum geometry only work moving forward.] So the firmware had to get out of every situation using only rotation and forward motion.

## Constraints

- **No backward movement, ever.** It isn't a preference. Reverse isn't a valid motor command in the firmware.
- **Falls are unrecoverable.** A missed cliff ends the run (and maybe the robot), so cliff checks must win over every other behaviour.
- **Rotation must be accurate without wheel encoders doing all the work.** Wheel slip on different floors makes timed turns unreliable.
- **Power budget.** The vacuum has turbo and eco modes that trade suction for battery life, and the motion logic has to work in both.
- **Microcontroller resources.** Everything runs on an ESP32-S3: [ADD: RTOS tasks or a superloop, sensor polling rates].

## Approach

<RobotStateDiagram />

The firmware is a small state machine with a strict priority order:

1. **Cliff check first, every tick.** If a downward-facing cliff sensor loses the floor, motors stop immediately, before any other logic runs.
2. **Obstacle check.** If the forward distance reading drops below the threshold, the robot stops.
3. **Rotate in place, closed-loop on the gyro.** The robot spins until the integrated gyroscope heading reaches the target angle, not for a fixed time. It picks the direction based on [ADD: the side sensor readings, alternation, or randomisation].
4. **Re-check, then drive forward.** It only moves again once the path ahead is clear and the floor is present. Otherwise it keeps rotating.

There is no `REVERSE` state. Removing it from the state machine is what makes the constraint enforceable: no code path can produce it.

### Gyro-closed-loop rotation

Timed turns ("spin for 400 ms") drift with battery voltage and floor friction. Instead, rotation integrates the gyroscope's yaw rate and stops at the target heading, slowing near the target to avoid overshoot.

```cpp
// Illustrative: rotate in place until the integrated yaw reaches the target.
void rotateBy(float targetDeg) {
  float yaw = 0;
  uint32_t last = micros();
  while (fabs(yaw) < fabs(targetDeg)) {
    if (cliffDetected()) { stopMotors(); return; }   // cliffs still win
    uint32_t now = micros();
    yaw += gyroZ() * (now - last) / 1e6f;           // deg/s * s
    last = now;
    float remaining = fabs(targetDeg) - fabs(yaw);
    spinInPlace(sign(targetDeg), remaining < 15 ? SLOW : NORMAL);
  }
  stopMotors();
}
```
