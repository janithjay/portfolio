## The bug

During tuning, changing the threshold stopped changing the results. The cause: the calibration step wrote its computed value into the **same** config field as the user's threshold. After the first calibration window, the configured threshold was gone, silently replaced, and every later run used the calibrated value instead.

```diff
- # calibration "helpfully" stores its result in the shared config
- config.threshold = baseline + k * noise_std
+ # calibration owns the baseline; the user owns the margin
+ state.baseline = baseline
+ effective = state.baseline + config.threshold_margin
```

### Why it hid so well

The bug produced plausible output. Detections still happened, just at a threshold nobody chose. With no error and no crash, the only symptom was "tuning has no effect", which is easy to blame on the data.

### What the fix changed

- Calibration state and user configuration live in separate objects, and calibration can't write to config at all.
- The effective threshold is computed, never stored, so there's one source of truth.
- A regression test sets a threshold, runs calibration, and asserts the configured value is unchanged.
